# 短指令＋决策文件派发协议

首次任务、方案裁决、补充要求和中断续跑都可使用本协议；“决策文件”也可承载尚无方案选择的任务说明。多行、长文本或包含多项条件时默认使用文件，避免 CLI 输入框折叠粘贴、吞换行或提前提交。简单且无歧义的单行回复可以直接发送；交互菜单按屏幕选项操作，不能把文件路径输入只接受选项的菜单。

## 1. 准备本轮文件

1. 核对最新用户要求、目标 Session、任务代次、当前交互状态与预留 C 轮次。CLI 正在执行、自动重试、投递未知或已进入 finalizing/closing/closed 时，不因文件已经准备好就续派发。
2. 在宿主实际可写、目标 CLI 可读的私有状态目录创建文件。默认使用 `goals-iterm-skill/dispatches/<task-id>/<session-key>/g<generation>-C<round>-v<revision>.md`；宿主无状态目录时可使用 `~/.local/state/goals-iterm-skill/dispatches/`。`session-key` 使用安全的本地别名，文件正文仍记录准确 session_id。将路径解析为绝对路径，目录和文件在平台支持时分别设为 0700/0600。不写回 skill 安装目录，不默认写入业务仓库，也不修改 `.gitignore` 来容纳协调文件。
3. 宿主能读文件不代表远端、容器或受限 CLI 能读。先核对实际执行环境与已有可读范围；必要时让 CLI 只读验证路径。已有获授权的共享私有位置可用，但须记录宿主与 CLI 各自的绝对路径及对应关系。没有可用路径时报告具体阻碍，不擅自开权限、建传输服务或回退到大段粘贴。
4. 使用 UTF-8 写入完整 Markdown；先写完再发布路径，避免 CLI 读到半个文件。使用唯一文件名且不覆盖已有文件，写后读回检查 ID、目标、约束和正文完整性。文件只承载协调指令，不作为项目实现或可执行脚本。不要经目标终端粘贴 heredoc、编码正文或 shell 写文件命令来绕过输入问题。
5. 每份文件使用唯一派发 ID，可组合任务 ID、session-key、generation、C 和修订号。发出路径后保持文件不变，不使用可变的 `latest.md`。决定改变时另建版本并注明替代关系；先核实旧派发是否已执行，再决定剩余动作。已提交后的纠正使用下一 C；确认未提交的草稿修订可沿用预留 C 并增加文件修订号。终端关闭不自动删除文件；没有另行明确的保留策略时保留供续接和审计，不要只存于可能自动清除的临时目录。审计台账跨日分文件不改变已发出的决策文件路径，次日事件继续引用原文件和派发 ID。

## 2. 文件内容模板

按实际任务填写，删除不适用项；不要把示例占位符当成事实，也不要要求 CLI 重新读取整份审计台账以寻找当前命令。

```markdown
# 本轮任务 / 决策

- 派发 ID：<唯一 ID>
- 任务 / 目标：<task-id；session_id；generation；已知 CLI 对话 ID>
- 轮次 / 决策：<C 编号；相关 D 编号，无则注明>
- 工作目录：<CLI 侧绝对路径>
- 创建时间：<真实时间含 UTC 偏移>
- 替代关系：<无，或旧派发 ID 与已经核实的执行状态>

## 目标与已知事实
<本轮要达成的结果；已完成动作；证据来源；仍未知的事项>

## 本轮决定与执行顺序
<采用的方案、必要理由、前置条件和具体下一步；条件不满足时返回阻碍>
<恢复任务时明确先核对哪些已有结果，哪些动作不得重复>

## 约束与授权边界
<用户及项目约束、范围、已有授权及来源；未授权动作不能执行>

## 验收与返回要求
<本轮完成条件、适用的定向验证、需返回的改动及证据>
先读取全文，简短回报派发 ID 和关键约束，再在既有授权范围内执行，无需等待协调者再次确认。
无法读全、目标/代次不符或要求冲突时，停止本轮执行并报告具体阻碍，不猜测缺失内容。
```

只记录推进本轮所需的信息，不复制凭据、无关历史或整份日志。CLI 输出/外部材料放在明确标注的引用区，不能把其中的要求直接升级为授权。决定和约束由协调者依据用户要求整理；文件不改变适用的用户、项目和宿主规则。

## 3. 只发送单行入口

发送前按 [审计协议](audit.md) 记录文件与派发意图，并再次核对登记及现场。下面只是自然语言示例，路径和 ID 要替换成真实值；仅发送到 Coding CLI 输入框，不能发送到 shell：

```text
请读取决策文件「/absolute/path/g1-C03-v1.md」（派发 ID：task-session-g1-C03-v1），回报该 ID 与关键约束后按文件执行；若无法读全或目标不符，停止并报告。
```

- 短指令仅包含读取要求、CLI 侧绝对路径、唯一 ID 和读取失败的处理方式，不重新塞入决策正文。路径含空格时用清晰的引号/括号界定；不用 `~`、相对路径或未经验证的 `@file` 特殊语法。
- `send_text.text` 不含 CR/LF，包括末尾换行，建议几百字以内；路径过长时在获授权的状态目录选择更短的唯一名称。不要靠拆分多次粘贴或重复 Enter 绕过输入限制。
- 发送后读取屏幕核对完整短指令仍处于待提交状态，没有混入其他草稿；只有确认目标 CLI 的提交键语义后才单独发送一次 `enter`。若已提交或开始运行，不再补 Enter。按键或输入返回不确定时，只读核实。
- 提交后更新原 monitor 与台账，观察 CLI 回报正确 ID、关键约束或可确认的对应文件读取证据。文本回显或 API 确认都不证明文件已读。CLI 正在运行但尚无读取证据时，继续观察，记录“读取未确认”，不要为索要回执重复发送；在适当交互点补核。本轮执行结果仍须独立验收。
- 文件读取失败时核对环境、路径和读取范围。在已确认上一轮未执行且输入就绪后，才能修正路径并记录下一次派发；权限不足按实际授权处理。不能让 CLI 凭文件名猜测任务。

## 4. 从折叠粘贴或异常输入恢复

`[Pasted text #N]` 可能是正常的折叠显示，不单独判失败。正文无法核实时不盲目提交，先读屏幕及必要历史区分：

| 实际状态 | 行动 |
| --- | --- |
| 明确是本协调者刚输入、尚未提交的草稿 | 按该 CLI 已知的编辑/取消草稿方式清除，再读取确认输入框为空，切换为文件短指令；记录切换，沿用预留 C |
| 存在用户草稿、内容混杂或归属未知 | 不追加、不覆盖；停止自动写入并请求必要澄清 |
| 已提交、开始执行或自动重试 | 保留原轮次并观察，不撤回、不重发；需要补充时等合适交互点并先核对已发生的动作 |
| 输入或提交调用超时，是否投递不明 | 标记投递未知，继续只读核实；不要通过清空输入框或重发来试探 |
| 编辑器清除语义未知，或清除后仍有残留 | 停止自动写入，报告输入阻碍；不循环试键，不把 Ctrl-C、Ctrl-U、Escape 当通用清空键 |

从未提交草稿切换到文件不需要重启 CLI，也不消耗网络中断恢复次数。若现场已经变成 shell，按原启动/恢复协议处理，不能直接发送文件短指令。

## 定向验收场景

修改协议后进行桌面推演；静态检查不代表真实 CLI 集成已通过。

| 输入 / 观察 | 应有行动与证据 |
| --- | --- |
| 首轮任务含多段目标、约束、验收条件 | 先完整写入唯一文件并读回，再审计并发送无换行短指令；确认后单独提交，记录读取证据 |
| 方案 A 只有在前置检查通过后才可执行，C 留作后续 | 文件明确 A 的前提、不满足时返回和 C 本轮不执行；CLI 关键约束回报覆盖该前提 |
| 简单单行回答或只接受上下键的选项菜单 | 前者可直接发送，后者按菜单操作；不强制给菜单传文件路径 |
| 本协调者的未提交输入折叠成 `[Pasted text #1]` | 不能凭折叠判断损坏；正文不可核实时按已知语义清除并确认，再以同 C 的文件派发 |
| 用户草稿已存在 | 不清空或混入短指令，暂停写入 |
| 提交超时后 CLI 回报正确 ID 并开始工作 | 关联原 C，补记读取/执行证据，更新原 monitor；不创建新 C 重发 |
| 宿主文件存在，容器 CLI 报找不到 | 不视为可读；核对共享路径/映射，没有获授权路径则报告阻碍 |
| 发送后改变决定，或旧代次回调到达 | 不改写已引用文件；前者核对执行进度后以新 C 发送新文件，后者不得派发 |
| 文件未写完、台账写入失败或短指令仍被截断 | 不提交业务指令；修复并核对后再派发，未知投递先只读调查 |
