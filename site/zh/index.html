  1. 连接 goals-iterm-mcp

    在 Mac 上启用 iTerm2 Python API，将本地 MCP 服务器配置到协调代理的客户端。检查工具发现并调用 list_sessions。

    MCP 安装指南

  2. 准备执行任务的 CLI

    在 iTerm2 中安装并登录 Claude Code、Codex CLI 或其他目标 CLI，确认新标签页中也能正常启动。

  3. 安装完整 Skill 目录

    按目标客户端支持的 Skill 机制安装，保留 goals-iterm-skill 目录下的 SKILL.md、references/ 和 agents/，再按客户端要求重新加载。

    完整安装说明

  4. 明确任务与验收标准

    指定项目路径和执行 CLI，写出可观察的完成标准，并要求代理使用 goals-iterm-skill。可以从下面的示例开始。

持续监控需要宿主的调度或唤醒机制，或在活跃的代理运行期间轮询。Skill 不自带后台服务；没有唤醒机制时，代理运行结束后无法继续监控。

任务示例

把委托要求说清楚。

使用 goals-iterm-skill，让 iTerm 中的 Claude Code 修复 /path/to/project 的登录问题。
先诊断，再修复，只运行相关测试。每次下发指令后监控进度，并处理常规技术决策。
仅在任务已经停止且不会自行恢复时，处理网络失败并续跑。
持续记录 Markdown 审计台账。通过验收后停止监控，汇总改动、测试和剩余问题。
不要发布。

开始之前。

安装 Skill 会自动安装 MCP 吗？

不会。需要单独在协调客户端连接 goals-iterm-mcp。仅安装 Skill 不会获得终端工具。

可以接管正在执行的 CLI 会话吗？

可以。先确认准确的会话 ID 和当前执行状态，再接管监控，避免重复下发仍在执行的任务。

审计台账会记录什么？

包括指令、CLI 反馈、决策及依据、投递结果、恢复、验收证据和收尾操作，附时间戳及关联事件 ID。它是操作记录，不是完整终端录像。

必须使用 Goal 功能吗？

不必须。宿主支持 Goal 时可以用来跟踪多步目标；不支持时也可以使用此流程。Goal 不替代监控，也不会自行提供后台唤醒。

从终端连接开始。
