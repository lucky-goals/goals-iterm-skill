  1. Connect goals-iterm-mcp

    On your Mac, enable the iTerm2 Python API and configure the local MCP server in the coordinating agent’s client. Verify tool discovery and list_sessions.

    MCP installation guide

  2. Prepare the execution CLI

    Install and authenticate Claude Code, Codex CLI, or your chosen CLI in iTerm2. Confirm it works in a new terminal tab.

  3. Install the whole skill package

    Use your client’s supported skill mechanism. Keep SKILL.md, references/, and agents/ together under goals-iterm-skill, then reload skills as the client requires.

    Full installation guide

  4. Set the task and acceptance criteria

    Name the project and CLI, define observable completion criteria, and ask the agent to use goals-iterm-skill. Start with the example below.

Continuous monitoring needs host scheduling or wakeups, or polling during an active agent run. The skill does not provide a background service and cannot keep monitoring after the run ends without a wakeup mechanism.

Example prompt

Make the handoff explicit.

Use goals-iterm-skill to have Claude Code in iTerm fix the login issue in
/path/to/project. Diagnose first, then fix it and run only relevant tests.
Monitor after every instruction, make routine technical decisions, and recover
from network failures only when the task has stopped and will not resume itself.
After acceptance checks pass, stop monitoring and summarize changes, tests,
and remaining issues. Do not publish.

Before you begin.

Does installing the skill install MCP too?

No. Connect goals-iterm-mcp separately in the coordinating client. Installing the skill alone does not expose terminal tools.

Can it take over an existing CLI session?

Yes. It first resolves the exact session ID and checks whether work is already running, so it can continue monitoring without duplicating the task.

What goes into the audit ledger?

Instructions, CLI feedback, decisions and their basis, delivery results, recovery, acceptance evidence, and cleanup. Entries include timestamps and linked event IDs. The ledger is an operational record, not a full terminal recording.

Do I need a Goal feature?

No. A supported host’s Goal feature can track a multi-step objective, but the workflow can also be used without it. A Goal does not replace a monitor or supply background wakeups.
