# goals-iterm-skill

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md)

coding agent から [goals-iterm-mcp](https://github.com/lucky-goals/goals-iterm-mcp) を通じて、iTerm2 上の Claude Code、Codex などの CLI に作業を指示する skill です。進捗の監視、判断の支援、完了条件の確認まで継続して行います。

## coding agent にインストールを依頼する

以下のプロンプトを、ローカルファイルにアクセスできる coding agent に渡してください。`[対象クライアント]` は skill をインストールするクライアント名に置き換えます。ローカルに取得済みのリポジトリがある場合は、URL をその絶対パスに置き換えることもできます。

```text
goals-iterm-skill を [対象クライアント] にインストールしてください。
リポジトリ：https://github.com/lucky-goals/goals-iterm-skill

1. 対象クライアントの既存設定と、対応する skill のインストール方法を確認し、
   公式の手順に従って配置先と適用範囲を決めてください。設定パスを推測しないでください。
2. リポジトリを取得するか、私が指定したローカルディレクトリを使用してください。
   SKILL.md と参照先ファイルを確認してください。リポジトリのルートが skill パッケージです。
3. goals-iterm-skill というディレクトリ名で、SKILL.md、references/、agents/ を
   まとめて配置してください。SKILL.md だけをコピーしないでください。既存のインストールが
   ある場合は差分を確認し、ローカル変更を保持して更新前にバックアップしてください。
   他の skill は変更しないでください。
4. 対象クライアントが goals-iterm-mcp に接続済みか確認してください。skill のインストールに
   MCP サーバーの導入は含まれません。未設定なら前提条件と設定手順を示し、無関係な
   MCP 設定は変更しないでください。
5. skill のメタデータと相対参照を検証してください。対応する方法で再読み込みし、手動操作が
   必要なら具体的な手順を示してください。確認可能なら、対象クライアントが実際に skill を
   認識したことも確認してください。
6. MCP が利用可能ならツールの検出を確認し、接続確認には list_sessions のみを使用して
   ください。インストール中は端末内容の読み取り、入力の送信、ウィンドウの作成、coding
   タスクの開始を行わないでください。
7. 配置先、skill の認識状況、MCP の準備状況、利用可能な監視方式を報告してください。
   監視方式は宿主のスケジューリング/再開機能、または agent 実行中のポーリングです。
   実際に再開できる仕組みがなければ、バックグラウンド監視が可能だと説明しないでください。
```

## 前提条件と手動インストール

リポジトリのルートが skill パッケージです。宿主クライアントの対応する方法で、ディレクトリ全体を `goals-iterm-skill` としてインストールしてください。相対参照を維持するため、`SKILL.md`、`references/`、`agents/` を一緒に配置します。配置先と再読み込み方法は、対象クライアントのドキュメントおよび既存設定に従ってください。

この skill は MCP のインストールや独立したバックグラウンドサービスを提供しません。宿主で goals-iterm-mcp に接続し、iTerm2 Python API を有効にして、対象端末で CLI と認証を準備してください。セッション一覧、画面/履歴の読み取り、テキスト/キー送信のツールが必要です。新しい端末の作成には対応する作成ツールも必要です。

継続監視には、宿主のスケジューリング/再開機能、または agent の実行中に行うポーリングが必要です。バックグラウンドで agent を再開できないクライアントでは、agent の実行終了後に自動監視を継続できません。この制約を明確に報告するよう skill が指示します。

## 使用例

```text
goals-iterm-skill を使い、iTerm 上の Claude Code に /path/to/project の
ログイン問題を修正させてください。まず原因を調査し、修正後は関連テストだけを実行して
ください。指示するたびに応答を監視し、通常の技術判断はあなたが行ってください。
ネットワークエラーでタスクが停止し、自動再開しないと確認できた場合は復旧してください。
完了条件を満たしたら監視を停止し、変更、テスト、残っている問題をまとめてください。
公開・リリースは行わないでください。
```

既存セッションのニックネームを指定してタスクを引き継ぐこともできます。skill は正確な `session_id` を確認し、実行中の作業を重複して送信しません。

## 応用例：Goal を使ってタスク全体を完了まで進める

複数の段階があるタスクでは、宿主が対応している場合、調整役の Codex チャットに Goal を設定することを推奨します。iTerm 内で作業を実行する CLI に別の Goal を設定する必要はありません。Goal は全体の目標を保持し、skill は調整手順を指示し、monitor は端末の応答を監視します。Goal は monitor の代わりにはならず、独立したバックグラウンドサービスを提供するものでもありません。[公式 Goals ガイド](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)を参照してください。

以下の項目を置き換えて、調整役の Codex に渡してください。宿主が Goal に対応していない場合は、Goal の作成と完了の指示を省き、監視と完了条件の確認に関する指示を残してください。

```text
Codex Goal を作成して開始してください。$goals-iterm-skill を使い、
iTerm MCP 経由で端末内の Coding CLI に継続して指示し、以下のタスクが
完了条件を満たすまで進めてください。

プロジェクトディレクトリ：[絶対パス]
実行する CLI：[Claude Code / Codex CLI]
対象セッション：[既存のニックネームまたは ID。なければ専用セッションを作成]

タスクの目標：
[最終的に実現したい結果]

完了条件：
1. [確認可能な機能や動作]
2. [成功する必要がある関連テスト]
3. [納品するファイル、結果、または説明]

実行要件：
- あなたは調整、監視、判断、結果の確認を担当し、具体的な開発作業は対象 CLI に任せてください。
- 最初にセッションの状態を確認してください。タスクが既に実行中なら、重複して指示せず
  監視を引き継いでください。
- タスク、追加指示、判断、復旧指示を送るたびに、同じ monitor を作成または更新してください。
- 宿主で実際に使える監視機構を利用してください。バックグラウンドで再開できない場合は、
  実行中にポーリングを続け、その制約を正確に説明してください。「後で確認する」という
  約束だけで済ませないでください。
- 通常の技術判断は文脈とプロジェクトの規約に基づいて自ら行い、advisor として CLI の
  作業継続を支援してください。
- CLI が作業中または自動再試行中なら監視を続け、タスクを再送しないでください。
- タスクが停止し、自動再開しないことを確認した場合に限り、完了済みの作業を確認したうえで
  回数を制限して復旧してください。
- 途中経過の報告、待機中の入力欄、CLI の完了宣言だけでタスク全体が完了したと判断しないでください。
- 完了条件の証拠が不足していれば追加確認を求めてください。すべての条件を満たしたら monitor を
  停止し、Goal を完了にして、変更、検証結果、残っている問題をまとめてください。

制約：
- プロジェクトの AGENTS.md に従ってください。
- 関連するテストに絞り、必要がなければ全テストを実行しないでください。
- Python プロセスの起動時に --reload を使用しないでください。
- このタスクでは公開、プッシュ、破壊的操作を許可しません。
- 私の判断が必要な場合は、具体的な質問、推奨案、必要な操作を提示してください。
  文脈を保存し、関連する自動入力を停止してください。
```

## 保守と検証

入口は [SKILL.md](SKILL.md) です。ツールの仕様は [iterm-tools.md](references/iterm-tools.md)、監視、復旧、動作検証シナリオは [monitoring.md](references/monitoring.md) を参照してください。これらの指示ファイルは現在、簡体字中国語で記述されています。ツールの取り決めは cc-iterm-mcp の `src/goals_iterm_mcp/direct.py` に基づいていますが、実行時はインストール済みツールの schema を優先します。

変更後は skill の frontmatter と相対リンクを検証し、監視プロトコル末尾のシナリオを確認してください。実際の CLI 検証には専用のテストセッションを使い、指示の送信、判断、復旧、監視の終了処理を確認します。静的検証だけでは、バックグラウンドのスケジューリングや実際の CLI 連携が動作することは保証されません。
